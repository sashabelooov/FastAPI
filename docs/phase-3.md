# Phase 3 — Todo CRUD

## What we built
Full Todo CRUD with ownership protection — every todo belongs to the authenticated user.

## File creation order

### 1. `app/models/todo.py`
SQLAlchemy model for the `todos` table.
Fields: `title`, `description` (nullable), `is_completed`, `owner_id` (FK → users.id CASCADE).
Relationship: `owner` → `User` (not a column, loaded from users table on access).

### 2. `app/models/user.py` (updated)
Added reverse relationship: `todos: Mapped[list["Todo"]]` so `user.todos` works.

### 3. `app/models/__init__.py` (updated)
Added `from app.models.todo import Todo` so Alembic detects the new model.

### 4. `migrations/versions/xxxx_create_todos_table.py`
Generated by `alembic revision --autogenerate`. Creates `todos` table with FK constraint.

### 5. `app/schemas/todo.py`
Three Pydantic schemas:
- `TodoCreate` — `title` (required), `description` (optional)
- `TodoUpdate` — all fields optional (PATCH semantics)
- `TodoResponse` — all fields except internal details. `from_attributes = True`.

### 6. `app/repositories/todo.py`
Database access for todos:
- `get_by_id` / `get_all_by_owner` / `create` / `update` / `delete`
- `update` uses `model_dump(exclude_unset=True)` — only updates fields the client sent

### 7. `app/services/todo.py`
Business logic:
- All operations verify ownership via `_get_owned_todo`
- `_get_owned_todo` raises `404` if not found, `403` if wrong owner
- Private method (`_`) extracted to avoid repeating fetch + ownership check three times

### 8. `app/api/v1/endpoints/todos.py`
Five endpoints, all protected with `get_current_user`:
- `GET /api/v1/todos/` → list user's todos
- `GET /api/v1/todos/{id}` → single todo
- `POST /api/v1/todos/` → create (201)
- `PATCH /api/v1/todos/{id}` → partial update
- `DELETE /api/v1/todos/{id}` → delete (204)

### 9. `app/api/v1/router.py` (updated)
Added `todos.router`.

## Key decisions

| Decision | Reason |
|----------|--------|
| `ondelete="CASCADE"` on FK | Deleting a user automatically deletes their todos — no orphaned rows |
| `TodoUpdate` all fields optional | PATCH semantics — client sends only what changed |
| `exclude_unset=True` in update | Only sets fields the client sent, doesn't overwrite others with None |
| `_get_owned_todo` private method | DRY — fetch + 404 + 403 check reused across get_one, update, delete |
| `403` for wrong ownership | Don't confirm the todo exists to someone who doesn't own it |
| `204` for delete | Correct HTTP semantics — success with no response body |
| `PATCH` not `PUT` | Partial update matches optional fields in `TodoUpdate` |

## Principles applied
- **SoC** — route = HTTP only, service = ownership logic, repository = DB queries
- **DRY** — `_get_owned_todo` eliminates repeated fetch + ownership check
- **Defensive Programming** — ownership verified before every mutation, CASCADE prevents orphans
- **YAGNI** — no pagination, filtering, or sorting until needed
